# Changelog

## Unreleased

## 0.6.0 - 2026-11-23

- The NRPN and RPN values say their width (0.6 `value_bits`): the MIDI 2.0 controllers import writes `7` for a `numSigBits` of 7 and `14` for any other width, and reads `value_bits` back for `numSigBits`; the Electra One preset, the pencilresearch/midi CSV and MIDNAM, which do not say the width, write `14` on every NRPN and RPN.

- The MIDI 2.0 controllers import reads the nine types of the norm (`cc`, `chPress`, `pPress`, `nrpn`, `rpn`, `pBend`, `pnrc`, `pnac`, `pnp`) and no longer makes a `params` block from a `param` type, which the list does not carry (a block of `osd` asks three SysEx fields that a controller list does not say); a type of the norm that the descriptor has no field for (`chPress`, `pPress`, `pBend`, `pnrc`, `pnac`, `pnp`) is a loss, and the entry is not carried. Any other value of `ctrlType` is refused.

- The Electra One import converts a SysEx template instead of losing every computed byte. A checksum element of the preset (`roland`, `waldorf`, `fractal`; `start` as a number or text; `length` optional) becomes OSD's checksum (`twos7`, `sum7`, `xor7`, with `from` and `length`); an unknown algorithm or a missing start is a loss at `/controls/N/values/M/message`, and no half-written command is kept. A value byte (7 bits, or two bytes msb/lsb) becomes a command argument (`u7`, `u14_msb`, `u14_lsb`). A parameter byte, a Lua function (named, never read nor run) and any other element without an OSD form are losses naming the control. The source keeps `revision` (passed by the caller in `Source`), `sha256` (of the preset text received, computed by the import) and `parameter_numbers`. `docs/electra-one.md` lists, per behaviour of the former SyntHub importer, whether it is kept (with its case) or lost. Reason: a preset shared for one controller keeps the messages that make the device answer; Electra One drivers already published by SyntHub may change on a new import, where a byte built at send time has no OSD form.

- The MIDI 2.0 Property Exchange controllers export and import say the norm's numbers (M2-117-UM v1.0, with the scaling of M2-115-U v1.0.2). `channel` is written from 1 and read back to OSD's 0 to 15; the import refuses a channel above 16 with a reason that names its Group (17-32 is Group 2), and a channel of 0 or below. `default` and `minMax` are written as unsigned 32-bit values scaled from the control's raw values with `numSigBits` (Min-Center-Max for Control Change, NRPN and RPN of LSB 32 to 127; Zero-Extension for RPN of LSB 0 to 31), and the import scales them back (`numSigBits` absent is 32). A negative bound of `range` or a negative `default` is named as a loss and not written, the norm's values being unsigned. `docs/midi2-controllers.md` and `docs/controls.md` say it with the norm's words. Reason: a controller list written from an OSD descriptor is one a MIDI 2.0 device reads right.

- The pencilresearch/midi CSV export names, at `/cc_params/entries/N`, the loss of the order of a control's ways when the first way is an NRPN and the second a CC: the CSV does not say the order, and the import puts the CC first. The loss is not named when the NRPN default column carries the order (an NRPN first way of a different range, with a default), nor when the CC is first. `docs/midi-csv.md` says what the CSV carries of the order. Reason: a partner who goes through the CSV and back knows what the round trip loses.

- The OSCQuery export keeps a command whose address has captures: each capture stays `{name}` in its segment (`/track/{n}/volume` is a method under the containers `track` and `{n}`), with its arguments, bounds and parents; the loss « the address has a capture » no longer exists. A command whose address a node already holds, or with a method on its path, is still named in the losses at `/commands/N`. The import reads a segment, or a part of one, of the form `{name}` as a capture (the command's address is an array of text and capture segments), so OSCQuery, OSD, OSCQuery keeps these commands; a segment with braces that is no capture (`{a,b}`, `{1x}`, two captures side by side) is not imported and the losses name its place. Reason: the service's export and the descriptor 0.4 already wrote `{n}` in the path, and an agent drives « track 3 » through it.

- The pencilresearch/midi CSV places a control's default in the column of its first way: an NRPN first way whose range differs from the CC's exports it in `nrpn_default_value`, and the import makes the NRPN the first way of a row whose only default is in that column with ranges that differ, so the round trip keeps the value. With equal ranges, or a CC first, nothing changes. A default on a control whose first way is an RPN, with a CC or NRPN further on, is a loss at `/cc_params/entries/N/default`, written in no column.

- Each format says the media type and the extension of the file it writes: `Format::media_type` and `Format::extension` (extension without a dot), following the table of `docs/INTERFACE.md`, so osc-bridge and SyntHub write no case per format when they place an export or offer it for download. Types are IANA's where one exists (`application/json`, `application/xml`, `text/csv`). Departures, each with its reason in INTERFACE.md: `text/x-python` for KnobKraft (IANA registers none for Python; the usual type, that of Python's `mimetypes`), `application/xml` for MIDNAM (the MIDI Association declares no type), and `epr` for Electra One (the extension the maker's repository gives its presets; the maker's documentation names none).

- The KnobKraft skeleton states its own licence, `# SPDX-License-Identifier: AGPL-3.0-only`, before the credit of the sources. Each source whose licence is not allowed under the AGPL-3.0, or not recognised (none included), gets a warning line under its `# Source:` line and a loss at `/_sources/N/license`; the export never refuses for it. `docs/knobkraft.md` gives the piece of the licence and a line per allowed licence.

- `Format::Knobkraft` writes a device with sound transfers as a skeleton of a KnobKraft Orm adaptation (Python text, by Christof Ruch, AGPL-3.0): the credit of the sources, then `name`, `numberOfBanks`, `numberOfPatchesPerBank` and `createEditBufferRequest` with the constants the descriptor gives. Each other function of the adaptation interface, and each of these when the descriptor does not give its constant, is named as a loss with its reason. A descriptor without `_sources` is refused (`NoSources`), one without `sound_transfers` too (`NoSoundTransfers`, new `FaultKind`). An adaptation is never read nor run: `import` returns an `InvalidFile` fault. `docs/knobkraft.md` cites each function with its section of the programming guide and the revision of KnobKraft Orm.

- `Format::Deluge` writes a resolved descriptor as the device definition the Deluge firmware reads (`midiDevice` with `ccLabels`, one attribute per CC 0 to 119), so a shared descriptor names its commands on a Deluge as it is. The name of a command is the one the MIDI 2.0 export derives (role, else a section starting with `/`, else the OSC address), escaped for XML and written whole, since the Deluge does not cut it. The CCs come in ascending order; a second command on a CC, a command without a CC or above 119, and each field the format does not carry (range, named values, channel, `/_sources`) are named as losses at their JSON address. The sources' credit and licence go in an XML comment, with `--` broken so the document stays well formed. A descriptor without `_sources` is refused (`NoSources`). The Deluge is not imported: `import` returns an `InvalidFile` fault.

- The pencilresearch/midi CSV imports a row with a CC and an NRPN as one control (0.6): the CC is the first way, the NRPN the first of `also`, and the row's single range goes to each way; the control has one default, the CC's. The export writes one row per control, from its first CC way and its first NRPN way, the range the two ways share written once in the CC columns, so the round trip CSV, OSD, CSV of such a row loses nothing. A way a row cannot carry (a second CC or NRPN, an RPN) is a loss at its pointer `/cc_params/entries/N/also/M`; the round trip OSD, CSV, OSD is not promised for it. A way whose message an earlier row (or the base of `import_into`) already claims is left out and named as a loss at its cell, and a row left with no way is lost, so the imported descriptor reads in 0.6. The Electra One export names `also` as a loss: a preset binds one message to a control.
