# The pencilresearch/midi CSV

The columns of `template.csv` of github.com/pencilresearch/midi (commit 215c64e8d3b3, licence CC-BY-SA-4.0), and the fate of each in `osd-formats`. The importer turns a row into one control of `cc_params.entries`: a row with a CC and an NRPN is one control whose `ways` are the CC (the first way) then the NRPN, since a setting reached by two messages is one control; a row with neither is lost. A message is claimed once: a way whose message (kind, numbers; a 14-bit CC claims its LSB too) an earlier row or the base already holds is lost at its cell (`cc_msb` or `nrpn_msb`), the row keeps its other way, and a row left with none is lost, so an imported control claims no message that a control of an earlier row or of the base already claims, which the 0.7 reader, of the version the import produces, would refuse. The one range a row gives goes to both ways. The control has one default, in the space of its first way's range: when the NRPN is the more precise, the control gets `scale`, the CC's range, so that the default keeps its value. A default is judged on the scale of its way: its range, else 0 to 127 for a CC of one number and 0 to 16383 for a 14-bit pair or an NRPN; outside it, the default is lost at its cell and the rest of the row is carried. With a CC and an NRPN, the CC's default is taken; the NRPN's default alone (a CC default lost counts as absent) is taken with the CC staying first when the two ranges are equal, unless the row gives no range and the default is above 127; when the ranges differ, or in that last case, it makes the NRPN the first way and the CC the way after it, so the default stays in the NRPN's scale; the NRPN's default beside a CC default is lost. A `cc_lsb` equal to its `cc_msb` is no 14-bit pair, which takes two distinct numbers: the way is a CC of that one number, without `value_bits`, claimed once, and the cell `cc_lsb` is lost. The exporter writes one row per control, from its first CC way and its first NRPN way; the range the two ways share is written once, in the CC columns. Since the import gives the one range of a row to both ways, a control with a CC and an NRPN of which one way alone has a range, when the message of the other implies another scale (0 to 127 for a CC of one number or a 7-bit NRPN, 0 to 16383 for a 14-bit pair or a 14-bit NRPN), is written with both scales in the bounds columns: that range, and the implied scale. Imported back, each way keeps its scale, now carried as its `range`, and neither takes the other's. When the implied scale equals the range, the range is written once. The CSV does not say the order of the ways: the import puts the CC first, unless a default in `nrpn_default_value` beside a CC of another range, or above 127 on a row without a range, makes the NRPN first. A control whose first way is an NRPN and whose second is a CC, without that default, comes back CC first, and the export names it as a loss at the control (`/cc_params/entries/N`); with that default the order comes back and no loss is named. When the export itself writes a default in `nrpn_default_value` beside a CC, the row it writes comes back NRPN first, so a control in the order CC then NRPN written that way is named as a loss of the order at the control. Any other way (a second CC, a second NRPN, an RPN, a pressure, a bend, a note) is lost at its pointer (`/cc_params/entries/N/ways/M`): the round trip OSD, CSV, OSD is not promised for it, while the round trip CSV, OSD, CSV of a row loses nothing. The importer produces a 0.7 descriptor, whose controls carry a `default`. The exporter writes a control's default, which is in the reference scale (`scale`, else the range of the most precise way), unchanged, to the column of the way that gives that scale: `cc_default_value` when it is a CC, or an NRPN whose range equals the CC's (the import puts the CC first then); `nrpn_default_value` when it is an NRPN alone, or with a CC of another range, or, without a range on either, with a default above 127. The ranges compared here are those of the row: with one way alone with a range and another scale implied by the other, they differ, and the default goes to the column of the way that gives the reference scale, which the import puts first. A control with an NRPN and a 7-bit CC, neither with a range, whose default of 127 or less is on the scale of the NRPN, is written with the range each way implies in the bounds columns (CC 0 to 127, NRPN 0 to 16383) and the default in `nrpn_default_value`: imported back, the NRPN is the first way, each way keeps its scale, now carried as its `range`, and the default keeps its value on 0 to 16383; in the order CC then NRPN, the lost order is named at the control. A default on a control whose reference way is neither (an RPN) while a CC or NRPN comes later, or on a control with neither, is lost at `/cc_params/entries/N/default`, written in no column.

The CSV has no column for the width of an NRPN value, and the import reads every NRPN on 14 bits (data MSB and LSB). The export names the width of the NRPN way of 7 bits it writes on the row (alone or beside a CC, with or without a range) as a loss at `/cc_params/entries/N/ways/M/value_bits`; when the row writes no bounds for that way (neither its own nor the shared range), the loss also says that its scale becomes 0 to 16383. No range is added for it: on the way of 14 bits the import creates, a range of 0 to 127 would send the data LSB alone. When the row has no CC and the export writes in `nrpn_default_value` the default of such a way without a range, the cell is kept as it is and `/cc_params/entries/N/default` is named too: the import reads this default on the scale 0 to 16383, not 0 to 127.

| Column | Fate | Reason or note |
|---|---|---|
| `manufacturer` | `device.vendor` | the first row's; a different value on a later row is lost |
| `device` | `device.name` | the first row's; a different value on a later row is lost |
| `section` | `section` of the control | carried as it is |
| `parameter_name` | `title`; the address `osc` is built from section and name | an empty cell writes no `title`, and the address is never copied into it; an export without a `title` writes the address in the cell |
| `parameter_description` | `description` | carried as it is |
| `cc_msb` | `ways[]`, `ctrlType: cc`, `ctrlIndex[0]` | 0 to 127 |
| `cc_lsb` | `ctrlIndex[1]`, with `value_bits: 14` | the pair is a 14-bit control; equal to `cc_msb`, it is lost and the CC is written alone, without `value_bits` |
| `cc_min_value` | `range`, first bound | both bounds are needed, else the lone bound is lost |
| `cc_max_value` | `range`, second bound | both bounds are needed, else the lone bound is lost |
| `cc_default_value` | `default` | the default of a control whose first way is the CC (or an NRPN of the same range); lost when it is outside the control's range, or, without a range, outside 0 to 127 (a CC of one number) or 0 to 16383 (a 14-bit pair) |
| `nrpn_msb` | `ways[]`, `ctrlType: nrpn`, `ctrlIndex[0]` | 0 to 127; an NRPN needs both its MSB and its LSB, else the row loses it |
| `nrpn_lsb` | `ctrlIndex[1]` | 0 to 127 |
| `nrpn_min_value` | `range`, first bound | on the NRPN way; lost when the row has no NRPN |
| `nrpn_max_value` | `range`, second bound | on the NRPN way; lost when the row has no NRPN |
| `nrpn_default_value` | `default` | the default of a control whose first way is the NRPN: alone, or with a CC of a different range (the NRPN is then first); with equal ranges the CC stays first, unless the row gives no range and the default is above 127; lost when it is outside the range (without a range, 0 to 16383), beside a CC default, or when the row has no NRPN |
| `orientation` | `polarity` | `0-based` is `unipolar`, `centered` is `bipolar`; any other word is lost |
| `notes` | `notes` | carried as it is |
| `usage` | `value_description` | carried whole, never cut |

A control with no way (its message is to be completed) is written as a row with no CC and no NRPN, which an import takes for no control: the export names it as a loss at the control (`/cc_params/entries/N`), and each of its `scale`, `range`, `transmit`, `recognize` and `nrpn_lsb_range` at its pointer.

The date of the import the caller passes in its source (`imported_at`) is kept as the note `_imported_at` of the source added, its value unchanged, 0.7 having no field for it: a `_imported_at` the source already holds stays, and the date goes under `_imported_at_2` (then `_imported_at_3`, then the next number not taken). It is no loss, no date is invented, and the other keys of the source are kept.

The credit of the sources has no column in the format: the repository carries one licence for all its files (its `LICENSE`), and no file or column per device. The exporter lists `/sources` in its losses, once, whatever the number of sources, and writes no cell for it; `osd export midi-csv` prints on the error output the credit to carry with the file: for each source its author or url, its licence and its attribution. A device without sources is refused.
